# Analysis 后端接入设计(分析链路)

> 协作约定: 本文件先供审阅, **不执行实现**; 待「待确认项」逐条确认后再编码。
> 目标是以**前端 mock 的字段形态**为准倒推后端契约, 保证联调时前端只换数据源。

## 1. 目标与范围

```yaml
目标: 为前端 Home > Analysis 的 5 个视图提供真实数据(proxy / log / system / service, 以及后续追加项)。

本期范围:
  · proxy : 运行状态分布、操作追踪、Top-K 启动频次
  · log   : 按级别分布、按领域(domain)统计、warn 及以上追踪、总数与缓冲大小
  · system: 平台信息(id/key/value 列表)
  · service: 进程自身指标(cpu/ram/io/gc/heap/goroutine + bridge 正常率), 10s 采样

非目标(本期不做):
  · 历史区间聚合查询(按天/周)
  · 多进程/多实例聚合(仅当前进程 + bridge 子进程)
  · 图表本身的降采样/预聚合(前端窗口固定 30 点, 后端只给最近窗口)

依赖: github.com/shirou/gopsutil/v4 (进程 cpu/mem/io、系统信息)
```

## 3. SQLite 数据模型

```sql
-- 3.1 proxy 操作追踪
CREATE TABLE IF NOT EXISTS proxy_trace (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  proxy_id   TEXT    NOT NULL,
  name       TEXT    NOT NULL,
  listen     TEXT    NOT NULL DEFAULT '',
  action     TEXT    NOT NULL,          -- create|update|delete|start|stop|restart
  created_at INTEGER NOT NULL           -- UnixMilli
);
CREATE INDEX IF NOT EXISTS idx_proxy_trace_at     ON proxy_trace(created_at DESC);
CREATE INDEX IF NOT EXISTS idx_proxy_trace_action ON proxy_trace(action, created_at DESC);

-- 3.2 日志追踪(全量级别 + 领域, 供分布/领域统计/警告追踪统一计算)
CREATE TABLE IF NOT EXISTS log_trace (
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  level    TEXT    NOT NULL,            -- debug|info|warn|error
  domain   TEXT    NOT NULL,            -- 消息里第一个 ':' 之前的部分, 无冒号则 'app'
  message  TEXT    NOT NULL,
  extra    TEXT    NOT NULL DEFAULT '', -- 结构化附加字段拼串 k=v 去敏后
  created_at       INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_log_trace_at    ON log_trace(created_at DESC);
CREATE INDEX IF NOT EXISTS idx_log_trace_level ON log_trace(level, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_log_trace_domain ON log_trace(domain, created_at DESC);

-- 3.3 bridge 事件(用于正常率)
CREATE TABLE IF NOT EXISTS bridge_trace (
  id       INTEGER PRIMARY KEY AUTOINCREMENT,
  service  TEXT    NOT NULL,            -- node / proxy-worker / automation ...
  ok       INTEGER NOT NULL,            -- 1=正常事件 0=异常/断开
  created_at       INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_bridge_trace_at ON bridge_trace(service, created_at DESC);
```

```yaml
字段原则: 只存"能算出指标"的最小列; 不存大 JSON; 所有统计都走 SQL 聚合。
写入量预估: 日志高峰 ~200 行/秒 -> 10s 批量一次(约 2000 行), 用单事务 executemany。
保留策略(prune, 每次启动 + 每小时):
  · 行数上限: proxy_trace 50k / log_trace 200k / bridge_trace 50k
  · 时间上限: 7 天
  · 超限按 id 升序删除(聚集索引顺序删, 代价可控); 参数见 conf/analysis.json
```

## 4. 写入路径

```yaml
proxy_trace:
  · service/proxy 在 Create/Update/Delete/Start/Stop/Restart 成功处调用
    analysis.RecordProxyEvent(event)(异步投递到有界 channel, 满则丢弃并计数)
  · listen 取"实际生效的 host:port"(Start 后由后端写回的值)
log_trace:
  · analysis 在 Init 时订阅 domain/log.Streamer(log 引擎的二级总线)
  · 批量聚合(与 log 引擎同源的 120ms 窗口)后单事务写入; 失败重试 1 次后丢弃并计数
bridge_trace:
  · 订阅 bridge.connected(ok=1) / bridge.disconnected(ok=0)
  · 正常率 = count(ok=1) / count(*) over 窗口(默认 5min)
  · 说明: 这是"连接可用率", 不是"业务请求成功率"; 若需要请求级成功率,
    需要 bridge 消息层暴露计数器(见 §12 待确认)
```

## 5. service 指标采样

```yaml
采样: 固定 10s(与前端一致), 写入内存环形窗口(每资源 30 点 = 5min)
来源:
  · cpu        process.Percent(参与 1 次预热, 间隔取 10s)
  · ram        process.MemoryInfo -> rss / vms (MB)
  · io         process.IOCounters -> read / write 速率(MB/interval)
  · gc         runtime.ReadMemStats -> PauseTotalNs 增量(ms) + NumGC 增量
  · heap       ReadMemStats -> HeapAlloc / HeapSys (MB)
  · goroutine  runtime.NumGoroutine()
  · bridge     bridge_trace 正常率(%) + 当前 peers / 窗口内 errors(见 §4)
对外: Snapshot() 返回 intervalMs + pid + 每资源 {series[], samples[]}
  · 前端图表 x 轴用序号(per interval), 与 mock 一致
  · 服务列表: 取自 conf/bridge 的 daemon 名 + bridge_trace 中出现过的 service
```

## 6. system 信息采集

```yaml
原生读取(可简单实现):
  · OS / Kernel / Architecture : syscall.Uname
  · Distribution                : 读 /etc/os-release(PRETTY_NAME)
  · CPU 型号 / 核心数            : gopsutil cpu.Info() + runtime.NumCPU()
  · Memory 总量                 : gopsutil mem.VirtualMemory()
  · Runtime / Application       : runtime.Version() + 构建时注入的版本
  · Data/Log directory          : store 根 + conf/log 路径
  · Locale / Timezone           : os.Getenv(LANG) + time.Now().Location()
  · Uptime                      : 进程启动时间(analysis.Init 记录)

需要额外手段(本期先标注, 暂不实现):
  · GPU 型号           : 依赖 lspci / vulkaninfo / 平台 API —— 跨平台成本高, 留空或 "-"
  · WebView 版本       : WebKitGTK/Edge 版本需平台特定探测, 暂标"-"
  · Display 分辨率/缩放 : 需窗口引擎暴露(WebView 侧屏幕信息), 暂标"-"
说明: 上述三项在 §12 待确认中列出, 确认前不引入额外依赖。
```

## 7. API 契约(与前端 mock 对齐)

```yaml
绑定: api/web/analysis.go, 每个卡片一个方法, 便于前端独立刷新。

# proxy
ProxyStatuses() []{status,count}                       # running/stopped/error/exception
ProxyActions(limit int) []{id,proxyId,name,listen,action,at}
ProxyTopK(k int) []{name,count}                        # count = action='start' 的次数

# log
LogLevels() []{level,count}
LogDomains(limit int) []{id,domain,total,last}         # last = 最近一条该领域日志的 at
LogIssues(range string, limit int) []{id,level,message,extra,at}
                                                       # range: 0.5h|1h|4h|8h|24h
LogStats() {total,buffer}                              # total=log_trace 行数; buffer=log 引擎缓冲

# system
SystemInfo() []{id,key,value}

# service
ServiceSnapshot() {
  intervalMs: 10000,
  pid: <本进程 pid>,
  resources: {
    cpu:{series:[{key,label,unit}], samples:[{ts,values:{...}}]},
    ... 同上: ram/io/gc/heap/goroutine
  },
  bridge:{
    services:[{value,label}],
    current:"node",
    series:[{key,label,unit}],       # rate/peers/errors
    samples:[...]
  }
}
```

```yaml
分页与限流:
  · ProxyActions / LogIssues 默认 limit=200, 上限 1000
  · LogIssues 的 range 非法时回落到 1h

错误约定: 沿用现有 apperr(参数非法 -> CodeInvalid, 依赖缺失 -> CodeNotFound/CodeServiceFail)
空数据: 一律返回空数组(非 null), 前端已有空态处理。
```

### 13.6 分布空白根因: 聚合结构缺少 db 标签

```yaml

## 18. 构建注入: 实测流程与指令

```yaml
实现位置: src/build/Taskfile.yml -> build:server 的 go build 命令
  go build <BUILD_FLAGS> -ldflags="-w -s \
    -X .../domain/config.buildVersion=$(git describe --tags --abbrev=0) \
    -X .../domain/config.buildTime=$(date -u +%Y-%m-%dT%H:%M:%SZ) \
    -X .../domain/config.buildHash=$(git rev-parse --short HEAD)" -o bin/automan-server

为什么把 -X 放在命令里而不是 BUILD_FLAGS:
  · BUILD_FLAGS 同时会传给 wails3 generate bindings(-f ...);
    其中含 $(...) 时会被 task 当成命令解析(实测报
    "a command can only contain words and redirects; encountered )")，
    且 '' 引号会提前结束单引号变量。

正确指令(必须从 src 运行, 由 wails3 提供 ROOT_DIR/PACKAGE_MANAGER):
  cd src && wails3 task build:server        # 产出 src/bin/automan-server
  cd src && wails3 task build               # 桌面应用(与 server 同构)

实测(2026-10-27):
  · 构建成功: src/bin/automan-server 31MB
  · strings 校验: 含 buildTime=2026-10-27T12:48:03Z, buildHash=2353fcd
  · 独立探针(相同 -X 参数)输出: version="v9.9.9" buildTime="..." hash="abc1234"
      未加 -X 时三项均为空 => 注入路径确认有效
  · 版本: 仓库无 tag => buildVersion 为空; about 实际显示 conf/about.version(0.1.0)

注意:
  · 直接 `task -d src/build build:server` 会失败(ROOT_DIR/PACKAGE_MANAGER 未注入);
  · 桌面 build 任务目前未注入 -X(走 go build info 兜底), 需要时按 server 同样方式加。

## 21. Environment 真实组件(list 只读 / file 编辑)

```yaml

  · entry 不是数组   -> `entry "x" must be an array`
  · 条目非对象 / key 为空 / type 未知 / value 与 type 不符 -> 带序号与 key 的错误
  · 任一处错误 => ok=false, list 视图用 EmptyState 显示 errorTitle + 具体错误

  · list: **只读**三列(140 / 1fr / 1fr): Type(文本) / Env key / Env value
