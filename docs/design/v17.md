## 1. 目标与范围

```yaml
目标: 打通代理数据的 CRUD 链路 —— 前端页面 ↔ Wails 绑定 ↔ proxy srv ↔ sqlite(迁移建表/读写) -> 操作日志。
      **不含执行链路**(启动/停止/重启代理、whistle/libretto 运行态), 见第 11 节。

范围内:
  - 迁移基建: 引入 golang-migrate; `data/migrate/` 下按规范放 SQL; 启动时自动迁移
  - 后端: `service/proxy`(CRUD + 校验 + 操作日志, 持有 db store 与 logger) + `api/web/proxy.go`(Wails 服务) + bootstrap 装配
  - 后端: 代理表的完整定义(见第 3 节, **这一节请你审字段**)
  - 前端: proxy 页从 mock/页面内 state 切换到真实数据(列表/搜索/分页/新增/编辑/删除)
  - 日志: 必要的操作记录(info 级, 含 id/name 等关键字段)

范围外(执行链路, 另开一份文档):
  - node 侧 `src/bridge` -> `src/ipc` **重命名已完成**(仅目录与 9 处相对导入, tsc/esbuild/Go 内嵌构建均通过)
  - 引入 libretto / whistle 到桥接层、由 node runtime 启动/变更代理执行状态
  - status 的"真实"变更(数据链只读写 status 列, 不触发任何执行)
```

## 3. 代理的完整定义(本轮重点, **请审字段**)

### 3.1 表结构(`data/migrate/` 里的第一个迁移)

```sql
-- 000001_create_proxies.up.sql
CREATE TABLE IF NOT EXISTS proxies (
    id          TEXT    PRIMARY KEY,                 -- 应用生成的 ULID(与前端 string id 一致)
    name        TEXT    NOT NULL,                    -- 展示名/唯一标识(唯一索引)
    target      TEXT    NOT NULL,                    -- 上游地址 host:port
    status      TEXT    NOT NULL DEFAULT 'stopped',  -- 运行态(数据链只读写, 不触发执行)
    rules       TEXT    NOT NULL DEFAULT '',         -- whistle 规则文本(coder 的整块内容)
    description TEXT    NOT NULL DEFAULT '',         -- 备注(便于人读)
    created_at  INTEGER NOT NULL,                    -- unix 毫秒
    updated_at  INTEGER NOT NULL,                    -- unix 毫秒
    deleted_at  INTEGER NOT NULL,                    -- unix 毫秒
    CHECK (status IN ('running', 'stopped', 'error', 'exception'))
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_proxies_name ON proxies (name);
CREATE INDEX IF NOT EXISTS idx_proxies_status ON proxies (status);
CREATE INDEX IF NOT EXISTS idx_proxies_updated_at ON proxies (updated_at DESC);
```

```sql
-- 000001_create_proxies.down.sql
DROP INDEX IF EXISTS idx_proxies_updated_at;
DROP INDEX IF EXISTS idx_proxies_status;
DROP INDEX IF EXISTS idx_proxies_name;
DROP TABLE IF EXISTS proxies;
```

### 3.2 字段语义

| 字段 | 类型 | 可空 | 默认 | 说明 / 取值 |
|---|---|---|---|---|
| `id` | TEXT | 否 | — | 主键, 应用生成(ULID); 与前端 `ProxyRow.id` 一致 |
| `name` | TEXT | 否 | — | 唯一; 前端展示与搜索主键 |
| `target` | TEXT | 否 | — | 上游 `host:port` |
| `status` | TEXT | 否 | `stopped` | `running` / `stopped` / `error` / `exception`(CHECK) |
| `rules` | TEXT | 否 | `''` | 规则文本(整块), 对应 sheet 里的 coder |
| `description` | TEXT | 否 | `''` | 描述 |
| `created_at` | INTEGER | 否 | — | 创建时间(unix 毫秒) |
| `updated_at` | INTEGER | 否 | — | 最后修改(unix 毫秒) |
| `deleted_at` | INTEGER | 否 | — | 删除修改(unix 毫秒), 作为逻辑删除 |

### 3.3 为什么不放这些(先记录理由, 你可否决)

```yaml
执行相关(whistle 端口/启动参数/libretto 配置/进程 pid): 属执行链路 -> 留给 v18 定, 避免现在猜错形状
enabled(启用开关): 与 status 语义重叠(stopped 即未启用), 先不加
group/tags: 当前 UI 没有入口; 需要时加列 + 迁移即可(加列是向后兼容的)
[!notice 后续无需加列, rules就是所有 whistle 相关的启动参数, 以json存储.]
```

## 4. 迁移基建(golang-migrate)

```yaml
依赖: github.com/golang-migrate/migrate/v4 (+ source/iofs 读内嵌 FS, 不需要 database/sqlite 驱动封套,
      因为迁移可直接复用现有 *sqlx.DB)

规范: data/migrate/{version}_{title}.{up|down}.sql       # 例 000001_create_proxies.up.sql
      版本号零填充 6 位、递增; 每个 up 必须有对应 down; 迁移文件**只做 schema**, 不做业务数据

执行时机: database 引擎 Start 内, openSQLite 之后、queue.Launch 之前(此刻只有这一条连接, 无并发写)
          失败即返回错误 -> 启动中断(与"启动期问题直接抛出"的既有取向一致); dirty 状态同样中断并给出提示

引擎改动(最小): engine/database 新增 Option(与 confengine.WithFS(data) 同款)
  WithMigrations(fs fs.FS, dir string)      # bootstrap 传 data + "data/migrate"
  hmm: 目录名与 embed 根的对应 —— bootstrap 侧写 WithMigrations(data, "data/migrate")
  实现: iofs.New(fs, dir) -> migrate.NewWithSourceInstance("iofs", src, dsn) -> Up()
        DSN: sqlite3://<abs path>(migrate 的 sqlite3 驱动仅用于记录 schema_migrations, 直接复用文件)
        [!notice: 若你希望完全不引入 migrate 的 sqlite 驱动, 也可改用 migrate 的 iofs + 自建
                  schema_migrations 记录表(约 40 行代码); 默认走前者(标准做法, 依赖更少)]
```

## 6. 接口契约(对前端)

```yaml
List(query)  -> Page{Items []Proxy, Total int}
  Query = { Search string; Status string; Page int; PageSize int }
  # 服务端搜索(name LIKE %q% OR target LIKE %q%) + 服务端分页(LIMIT/OFFSET) + Total 供前端算页数
Get(id)      -> Proxy
Create(input)-> Proxy            # 生成 id/created_at/updated_at, status 缺省 stopped, endpoint 缺省 ''
Update(id, input) -> Proxy       # 只改允许的字段 + updated_at
Delete(id)   -> error # 逻辑删除
```

```yaml
ProxyInput = { Name string; Target string; Application string; Status string; Endpoint string; Rules string; Note string }
Proxy      = 上述字段 + ID/CreatedAt/UpdatedAt(毫秒)

校验(service 层, 全部返回明确错误):
  name   : 非空, ≤64, 唯一(冲突 -> 明确错误)
  target : 非空, ≤255, 形如 host[:port](宽松校验, 不做 DNS)
  application/status : 必须是枚举值(见第 3 节)
  endpoint: 可空; 非空时须是 http(s):// 开头
  rules/note : ≤64KiB
```

## 7. 操作日志(必要记录)

```yaml
info   proxy: created   id=… name=… target=…
info   proxy: updated   id=… name=… fields=name,target   # fields=被改动的列
info   proxy: deleted   id=… name=…
warn   proxy: rejected  op=create name=… err=duplicate name
error  proxy: failed    op=update id=… err=…
```
实现: `logger.Deliver(logkit.New(level, "proxy: …", logkit.F(...)))` —— 与 database/settings/bridge 引擎一致;
因此这些行会经日志引擎的 stream out 出现在前端 Logs 页(无需额外接线)。


## 12. 风险与取舍

```yaml
- 单连接(sqlite SetMaxOpenConns(1)): 迁移 + CRUD + 执行链路的状态回填会串行; 当前量级足够, 后续若成为瓶颈
  再把读迁到独立连接/只读副本
- 迁移不可逆风险: down 会丢数据(仅开发期使用); 生产路径只走 up, 且每次迁移前建议备份(后续 step 可加)
- 搜索用 LIKE: 数据量大时无索引收益; 当前规模可接受, 需要时上 FTS5(另开)
- 前端一次性切数据源: 列表/分页/搜索全改, 回归面较大 —— 保留现有 UI 与交互不动, 只换数据来源与状态归属
```

## 20. 停止代理需要杀整个进程组(whistle 会 fork)

```yaml
发现: 现场存在残留的 whistle 进程 —— 命令行是 `starting ... run .../whistle/index.js` 与 `pfork/lib/main`,
      说明 whistle 的 `run` 只是 wrapper, 真正的代理在 fork 出来的子进程里。
      只 SIGTERM wrapper 的话, 子进程可能继续占着端口(8899/8900 就是被它们占用的)。
修法(node/service/proxy.ts):
  · spawn 时 `detached: true`(非 Windows): 让 whistle 树进入独立进程组
  · 停止时 signalTree(): 先 `process.kill(-pid, SIGTERM)`, 超时后 `process.kill(-pid, SIGKILL)`;
    组不存在时退回 child.kill(单进程)
仍需 GUI 验证: 点停止后 `pgrep -af whistle` 应为空, 端口释放。
```
