## 1. 目标与范围

```yaml
目标: 用户注册 / 登录 / 会话保持 —— 一条完整的本地链路。

范围内:
  - 存储: 用**同一个 sqlite 库**(与代理同库)分**用户表**与**登录日志表**
  - 会话: 引入 ttlcache 保存登录状态(定时过期 / 时间延长 / 过期 hook 发事件)
  - 启动恢复: 应用每次打开时, 按"登录日志表里当前用户的最后登录时间 + 生效的登录时长 - 现在 > 0"
    设置该会话的 cache 过期(见第 4 节)
  - 分层: **不新增 engine**, 只加 service(service/session) + api/web 暴露 + bootstrap 装配
  - 命名: 该链路统一用 `session`
  - 能力: 注册 / 登录 / 登出 / 校验 / 启动恢复 / 改密 / 用户 CRUD
  - 事件: `session:login` / `session:logout` / `session:signup`(由 window emit 到前端) + 过期事件
  - 配置: 会话时长取自设置项 `general.session.expirationS`(step1 已在默认层与 schema 登记)

范围外(后续):
  - 远程鉴权 / 多设备 / 第三方登录
  - 权限与角色体系(见第 11 节 K)
  - 前端页面改造(lib/auth.ts 换成真实 binding)属第 ③ 步收尾
  - 代理执行链路(v17 §11 的 v19)
```

```sql
    id         TEXT    PRIMARY KEY,
    user_id    TEXT    NOT NULL,                    -- 关联 users.id(不做外键约束, 便于保留历史)
    username   TEXT    NOT NULL,                    -- 冗余存一份, 便于失败(用户不存在)时也能审计
    result     TEXT    NOT NULL,                    -- success|failed
    reason     TEXT    NOT NULL DEFAULT '',         -- 失败原因(no such user / bad password / expired ...)
    token_hash TEXT    NOT NULL DEFAULT '',         -- 成功时记录本次会话 token 的哈希(供启动恢复校验)
    created_at         INTEGER NOT NULL                     -- unix 毫秒(记录创建时间 + 登录时间)
);
CREATE INDEX IF NOT EXISTS idx_login_logs_user_at ON login_logs (user_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_login_logs_at ON login_logs (created_at DESC);
```

## 4. 会话状态: ttlcache 与过期策略

```yaml
依赖(待确认 §11 A): github.com/jellydator/ttlcache/v3
  选它的理由: 维护中、内置 janitor 定时清理、有 OnEviction(ctx, reason, item) 钩子、
  支持 Set 覆盖以"延长"过期时间; 纯内存, 不引入额外存储

缓存形态:
  key   : session token(随机 128bit -> hex 字符串)
  value : Session{ UserID, Username, NickName, Token, CreatedAt, LastSeenAt, ExpiresAt }
  TTL   : 来自设置项 general.session.expirationS(生效值, 经 settings engine 读取)

  [!notice 服务之间通常不互相调用, 避免耦合]

三种生命周期动作:
  1) 定时过期: ttlcache 自带 janitor(每 TTL/10 或固定间隔)清理到期的会话
  2) 时间延长: 每次成功校验(Current/Resume)后按配置续期(默认滑动续期, 见 §11 F)
  3) 过期 hook: OnEviction 回调里判断 reason(Expired / Deleted / Overflow), 对 Expired 发
     `session.expired` 主总线事件 -> window 转 `session:expired` 给前端

启动恢复(你给的算法, 逐字落实):
  应用打开时前端带着本地保存的 token 调 `Resume(token)`:
    1) 在 login_logs 里取"该 token 哈希对应的最后一条成功登录记录"(按 at DESC 取 1 条)
    2) 计算剩余 = (登录时间 + expirationS*1000) - now
    3) 剩余 > 0  -> 用**该剩余时间**作为这条会话的 cache TTL, 写入缓存并返回用户信息
       剩余 <= 0 -> 视为已过期: 返回"需要重新登录"(不写缓存), 并记一条 login_logs(reason=expired)
  # 说明: token 不落库, 落库的是它的哈希(login_logs.token_hash) —— 于是"重启后凭本地 token 校验"
  #       成立, 且库里没有可直接复用的凭据
  # 备选(§11 E): 不校验 token, 只按"用户名 + 时间窗"恢复(更弱, 但实现更简单)

服务生命周期:
  session srv 持有 ttlcache 与 janitor; 构造后启动 janitor, 提供 Close()
  组合根在装配后 `defer sessionSrv.Close()`(bootstrap 里紧挨 registerServices, 见第 5 节)
```

## 6. 接口契约(对前端)

```yaml
会话:
  SignUp(input SignUpInput)   -> Session     # username/password/displayName?; 成功即登录(写缓存 + 记日志)
  SignIn(username, password)  -> Session     # 失败: 明确错误(用户不存在 / 密码错误), 并记 login_logs
  SignOut(token)              -> error       # 删缓存 + 记日志 + 发事件
  Resume(token)               -> Session     # 启动恢复(第 4 节算法)
  Current(token)              -> User        # 校验并(默认)续期
  ChangePassword(token, oldPassword, newPassword) -> error   # 改自己的密码

用户 CRUD(同一 srv):
  ListUsers(query) -> Page{Items,Total}      # 搜索 + 分页(口径与 proxy 一致: 搜索 name, 服务端分页)
  GetUser(id) / CreateUser(input) / UpdateUser(id, input) / DeleteUser(id)   # 逻辑删除
  ResetPassword(id, newPassword) -> error    # 管理侧改密(是否需要, 见 §11 K)

对外形态:
  Session = { Token string; User User; ExpiresAt int64 }        # ExpiresAt: unix 毫秒
  User    = { ID, Username, DisplayName, Role, CreatedAt, UpdatedAt }
  校验(service 层, 明确报错):
    username: 非空, 3..32, 只允许字母/数字/下划线/连字符; 未删除时唯一
    password: 长度 >= 8(与前端既有提示一致), <= 256
    displayName: <= 64
```

验收标准:

```yaml
- 注册: 新用户写库(bcrypt 哈希), 立即登录并能在重启后仍保持
- 登录: 正确密码进入应用; 错误密码被拒且 login_logs 有一条 failed(带原因)
- 会话保持: 重启应用 -> 仍处于登录态(剩余时间 = 登录时间 + expirationS - now)
- 过期: 把 expirationS 调小(或等它到期) -> 重启后要求重新登录, 且收到 session:expired/login rejected
- 改密: 旧密码错误被拒; 成功后旧会话失效(按 §11 结论)、可用新密码登录

- 日志: 上述每个动作在 Logs 页都能看到对应一行; login_logs 可查到成功/失败记录
```

## 13. 风险与取舍

```yaml
- 内存会话: 进程重启后缓存丢失, 靠 login_logs + 本地 token 恢复; 若用户清掉本地 token 则必须重新登录(预期)
- token 强度: 128bit 随机 + 只存哈希; 本地应用无网络面, 不引入签名/JWT(避免过度设计)
- ttlcache 的 janitor 是后台 goroutine: srv 必须提供 Close() 并由组合根调用, 否则退出时留协程
- bcrypt 开销: 登录/注册路径有一次约几十毫秒的哈希计算(可接受); 不要在列表等热路径上做哈希
- 与设置链路的耦合: 会话时长是"可被用户改的配置", srv 读的是**生效值**(三视图叠加结果),
  因此改配置后新登录立刻生效; 已存在的会话按写入时的 TTL 走, 不追溯(是否要追溯见 §11 F)
- 前端 token 存放位置决定"跨重启保持"是否成立(localStorage vs sessionStorage, 见 §11 H)
```
