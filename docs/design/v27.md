# Certificates 服务设计(全局证书管理)

> 协作约定: 先本文档明确细节, **确认后再执行**; 标记「待确认」的条目需要拍板。
> 参考既有约定: service 承载业务语义、engine 只做通用能力; 分层见 [backend workflow](../workflow/backend.md);
> 文件即事实来源 + store 引擎 + `text/template` 的写法参考 environments(v26); 本域暂无任何 Go 代码。

## 1. 目标与边界

```yaml
目标:
  · proxy 依赖 whistle, 而 whistle 的证书目录是**全局共享**的 —— 本服务把该目录作为唯一事实来源,
    维护一份可读、可编辑元数据、可同步的记录, 并让 UI 与之一致;
  · 面向 whistle 的全局证书目录(certDir)做五件事: 同步 / 导入 / 编辑元数据 / 导出 / 删除;
  · 记录持久化为 <store root>/<conf.certificate.root>/<conf.certificate.file>, 每个证书文件一条记录;
  · 同步时机: 程序启动、程序终止、ticker 到期、前端手动触发;
  · 同步过程**不产生 notice**(不打扰用户), 只在 log 里记一行汇总。

非目标(本期):
  · 不生成/签发/续期证书, 不做证书内容加解密;
  · 不把 certDir 传给 whistle 子进程(proxy.start 参数接线属下一步, 见 §10/待确认 11);
  · 不做按用户/workspace 隔离(全局共享是 whistle 的既有语义);
  · 不做文件内容的差异比对(只按存在性 + 文件元信息判断变化, 见 §6)。
```

## 2. 目录与文件布局

```yaml
store root: ~/.config/automan
  来源: conf/store.json root="." 经 internal/paths.Resolve -> <os.UserConfigDir()>/automan

记录文件: <store root>/<conf.certificate.root>/<conf.certificate.file>
  当前 conf/certificate.json: root="certs", file="certificates.json"
  => ~/.config/automan/certs/certificates.json
  ⚠ 需求描述为 .config/automan/cert/certificate.json, 与现值不同 -> 见待确认 1
  读写走 **store engine**(相对路径 certs/certificates.json), 原子写由引擎保证。

证书目录: conf/certificate.certDir = "${HOME}/.WhistleAppData/.whistle/certs/"
  · whistle 的全局证书目录, 位于 store root 之外 -> store engine 的 path 校验会拒绝绝对路径,
    因此该目录的读写由服务内 dirfs.go 直连 os 完成(见 §7), 并在文档中明确为规则例外;
  · 只展开 ${HOME} 一个变量(os.UserHomeDir); 包含其他 ${...} 或为空 -> Init 失败(不猜路径)。

模板: data/default/certificate.tpl.json
  · 内嵌只读; 由 certificate 服务用 text/template 渲染(§5)。
  · data/* 属用户定义内容, 除明确说明外**不允许修改**; 本服务只写记录文件, 不写 data/。
```

记录文件格式(单文件承载全部记录):

```json
{
    "meta": {
        "version": 1,
        "syncedAt": "2026-10-31T12:00:00+08:00"
    },
    "certificates": [
        {
            "id": 1,
            "name": "example.com",
            "type": "crt",
            "createdAt": "2026-10-31T12:00:00+08:00",
            "updatedAt": "2026-10-31T12:00:00+08:00",
            "certPath": "example.com.crt",
            "keyPath": "",
            "valid": "2027-01-01T00:00:00Z",
            "tags": []
        }
    ]
}
```

```yaml
规则:
  · certificates 按 id 升序落盘; UI 侧倒序显示(id 越大越新, 新建/导入在顶部);
  · 条数上限 = conf.certificate.limit(当前 256): 超出时**整轮同步失败并保留旧记录**(不静默截断);
  · 记录文件不存在 -> 视为空记录, 首次同步全量建立;
  · 记录文件损坏(JSON 解析失败) 的处理见待确认 10。
```

## 3. 领域契约(domain/certificate)

```go
// 证书类型 = 合法后缀(与前端 lib/certificate.ts 的 certificateTypes 一致)。
var Types = []string{"crt", "pem", "key"}

type Record struct {
    ID        int       `json:"id"`        // 自增, 不复用
    Name      string    `json:"name"`      // 允许重名; 导入时取自去后缀的文件名
    Type      string    `json:"type"`      // 即文件后缀(crt|pem|key)
    CreatedAt string    `json:"createdAt"` // RFC3339
    UpdatedAt string    `json:"updatedAt"` // RFC3339
    CertPath  string    `json:"certPath"`  // 相对 certDir; 记录不存绝对路径
    KeyPath   string    `json:"keyPath"`   // 同名 .key 存在时填充, 否则空
    Valid     string    `json:"valid"`     // 证书有效期(PEM 解析结果), 语义见待确认 3
    Tags      []string  `json:"tags"`      // 用户自定义, 同步不覆盖
}

type Snapshot struct {
    SyncedAt string   `json:"syncedAt"`
    Records  []Record `json:"records"`
}

// Document 是 UI 的展示单元: 记录 + 模板渲染后的原文(pretty JSON)。
type Document struct {
    Record  Record `json:"record"`
    Content string `json:"content"`
}

// Stats 是一次同步的汇总(只进 log, 不进 notice)。
type Stats struct {
    Scanned int `json:"scanned"`
    Added   int `json:"added"`
    Removed int `json:"removed"`
    Updated int `json:"updated"`
    Skipped int `json:"skipped"`
}
```

```go
// 领域错误(api 层映射为 apperr, 见 §8)
var (
    ErrInvalidPath = errors.New("certificate: invalid path")
    ErrNotFound    = errors.New("certificate: not found")
    ErrExists      = errors.New("certificate: target already exists")
    ErrInvalidCert = errors.New("certificate: unsupported certificate file")
    ErrLimit       = errors.New("certificate: record limit exceeded")
    ErrInvalidFile = errors.New("certificate: invalid record document")
    ErrUnknownPlace = errors.New("certificate: unknown template placeholder")
)
```

## 5. 模板渲染(data/default/certificate.tpl.json)

模板原文(用户定义, 只读):

```json
{
    "name": "{{.Name}}",
    "type": "{{.Type}}",
    "createdAt": "{{.CreatedAt}}",
    "updatedAt": "{{.UpdatedAt}}",
    "certPath": "{{.CertPath}}",
    "keyPath": "{{.KeyPath}}",
    "valid": "{{.Valid}}",
    "tags": []
}
```

```yaml
渲染: text/template(见 backend workflow 细节 14, 与 environments 一致)
  ctx := certificateTemplateData{Name, Type, CreatedAt, UpdatedAt, CertPath, KeyPath, Valid}

  · 语法错误 -> ErrInvalidFile;
  · 未知字段(执行期报错) -> ErrUnknownPlace;
  · 渲染结果必须能 JSON 解析, 否则该 item 跳过 + log warn(不中断整轮同步);
  · 模板只读: 服务不重写/不格式化用户模板; 渲染结果只是该 item 的展示原文(记录才是结构化事实)。

单个 item 的生成时机: **首次同步(记录里还没有该 certPath 时)** 用当前文件信息渲染一次;
  之后 updatedAt/valid 变化时只更新记录字段, 不重新渲染整份原文(避免覆盖用户编辑过的元数据)。
```

## 6. 同步模型(唯一事实与一致性)

```yaml
事实链(单向, 不可逆):
  certDir(文件系统) -> 服务记录(内存) -> 事件通知 UI 重载 -> 记录文件落盘

一致性要求: certDir / 记录文件 / UI 显示 / 服务内存 四者收敛到同一份记录集合。

时机:
  · 程序启动: Init() 内首次 Sync(); 失败只 log Warn, 不阻断启动(仿 environments/analysis 的装配写法);
  · ticker: syncIntervalMs 到期触发 Sync();
  · 程序终止: Stop() 内再 Sync() 一次(落盘收敛);
      ⚠ 当前 bootstrap 只有 session.Close 串进 cleanup, 本服务必须把 Stop 合并进
        registerServices 的返回(否则终止同步不会执行) —— 见 §7。

差异规则(key = certPath):
  · 扫描到 / 记录无 -> 新增: id = max(id)+1, createdAt = updatedAt = now, certPath/keyPath 取自文件, 渲染模板;
  · 记录有 / 扫描无 -> 删除记录(文件被外部删除); 只删记录, 不碰任何文件;
  · 两侧都有         -> 文件 mtime/size 变化时刷新 updatedAt(与 valid), 否则完全不动(幂等, 不写文件);
  · 后缀不在 Types 内、无法解析 PEM、隐藏文件(以 "." 开头)、临时文件(.automan-tmp-*) -> 跳过 + log warn 计数;
  · 记录数将超过 limit -> 整轮同步失败, 保留旧记录, log error。

日志(不 notice):
  logkit.New(LevelInfo, "certificate: synced",
             F("scanned", n), F("added", n), F("removed", n), F("updated", n), F("skipped", n))
  失败项: LevelWarn + 文件名 + 原因; 整轮失败: LevelError。

重命名语义: 文件改名 = 删除旧记录 + 新增记录(新 id);
  不做 inode/内容指纹跟踪(见待确认 12)。
```

## 7. 服务实现(service/certificate)

```yaml
接口形状: Key/New() 无参 + WithX() 链式注入 + Init()/Stop()
  WithStore   store engine(记录文件)
  WithData    内嵌 data(模板)
  WithConfig  conf/certificate
  WithLogger  日志
  WithNotice  预留(本期同步不发 notice; 若前端动作成功提示需要, 复用同一注入)

文件拆分(单文件单一职责, 首行注明):
  certificate.go  Key/New/With*/Init/Stop/List/Read/Sync/Import/Update/Export/Delete/校验
  store.go        记录文件适配(do/fullPath/readFile/writeFile, 全部相对路径, 走 store engine)
  dirfs.go        certDir 外部目录适配: 绝对路径拼接 + 逃逸校验 + 原子写(临时文件 .automan-tmp-* + rename) + 列目录
  scan.go         扫描 certDir、解析文件名/后缀、PEM 解析(encoding/pem + crypto/x509) 得出 valid
  document.go     模板渲染 + 记录 JSON 编解码 + 数值/字段校验
  record.go       id 分配、排序、limit、时间格式化、快照构造

方法契约:
  List()                      -> Snapshot          # 内存快照(id 升序)
  Read(id)                    -> Document          # 记录 + 渲染原文
  Sync()                      -> (Snapshot, Stats) # 手动/定时/终止同步共用同一条实现
  Import(path string)         -> Document          # 复制到 certDir + 填充 inspect 信息
  Update(id int, content string) -> Document       # 只更新元数据(见下)
  Export(id int, target string)  -> error          # 复制到 target(可重命名; store 无 copy -> rw)
  Delete(id int, removeFile bool) -> error         # 只删映射 / 连 certDir 文件一起删

Import:
  · 源文件后缀必须在 Types 内, 否则 ErrInvalidCert;
  · 目标名 = <源文件名>(保留后缀) 落在 certDir; 已存在 -> ErrExists(不覆盖);
  · name = 去后缀文件名, type = 后缀, createdAt = updatedAt = now,
    certPath = 目标相对路径, keyPath = 同名 .key 存在时填充;
  · inspect: 解析 PEM 首块 x509 证书 -> valid(见待确认 3); 解析失败 -> ErrInvalidCert(导入是显式动作, 失败要提示);
  · 写入 certDir 后立即重算记录并落盘(不等待下一轮 ticker)。

Update(编辑保存):
  · 入参是 UI 编辑区里的**文档原文**; 解析后只取模板定义的元数据键(name/tags/valid),
    其余键(id/certPath/keyPath/createdAt/type)只读 -> 出现差异时 ErrInvalidFile;
  · 更新 updatedAt = now, 重新渲染原文返回; **不改动 certDir 里的证书文件**。

Export:
  · target 由前端原生保存对话框给出(绝对路径, 可重命名);
  · store 引擎没有 copy -> 先读 certDir 源文件再写 target(rw 思路), 写用 dirfs 的原子写;
  · target 已存在 -> ErrExists(由对话框负责覆盖交互, 服务不静默覆盖);
  · 仅导出该记录对应的单文件(不导出 keyPath)。

Delete:
  · removeFile=false: 只从记录里移除(下次同步若文件仍在 -> 会被重新加回, 见待确认 6);
  · removeFile=true: 同时删除 certDir 中该文件(仅该文件, 不删同名 .key);
  · 两种情况都从内存移除并落盘, 失败 -> ErrNotFound。

并发:
  · 记录/内存: RWMutex; 读写 API 短暂持锁;
  · 同步: 单独 syncMu 串行化(启动/ticker/手动可能并发), 扫描在锁外进行,
    合并 + 落盘在写锁内完成(见待确认 9);
  · certDir 写(导入/删除/导出) 与扫描互斥于 syncMu, 避免扫到半成品;
  · 记录文件原子写由 store engine 保证; certDir 写入由 dirfs 的 tmp+rename 保证。
```

## 8. API 契约(api/web/certificate.go)

```yaml
List()                          -> Snapshot
Read(id int)                    -> Document
Sync()                          -> Snapshot
Import(path string)             -> Document
Update(id int, content string)  -> Document
Export(id int, target string)   -> error
Delete(id int, removeFile bool) -> error
```

```yaml
错误约定(沿用 apperr):
  · 后缀不支持 / PEM 解析失败 / 文档 JSON 非法 / 越权改只读键 -> CodeInvalid
  · 记录不存在                                            -> CodeNotFound
  · 目标文件已存在(导入/导出)                             -> CodeAlreadyExists
  · 记录数超限                                            -> CodeFailedPrecondition
  · 记录文件损坏 / certDir 读取失败                       -> CodeInternal + 明确文案
```

## 10. 与 proxy / whistle 的关系

```yaml
· whistle 的证书目录是全局的(certDir 单点), 多个 proxy 实例共享同一份证书 —— 本服务**不感知 proxy 实例**;
· data/default/proxy.rules.json 里有 certDir 字段, 但 Go 侧 rules 结构体
  (backend/service/proxy/start.go: rules{Host,Port,UIPort,Timeout,DNSServer}) 尚无该字段,
  启动请求也不传给 node -> 本期**不接线**, 只保证 certDir 的唯一来源是 conf/certificate.json(待确认 11);
· 若后续接线: proxy.start 增加 certDir(或 node 侧直接读取 whistle 全局目录), 本服务不参与启动参数拼装。
```
