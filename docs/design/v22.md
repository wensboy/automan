## 2. 目标形态

```yaml
main.go:
  os.Exit(cli.Execute(ctx))            # 唯一出口, 退出码由 Execute 返回

分层:
  data/conf/command.json#cli   -> 声明式命令树(唯一数据源, 不写死在代码里)
  domain/config/command.go     -> CLI 段的结构映射(递归 Command)
  internal/cli/                -> 配置 -> *cli.Command 树; 建立 path->node 的 map(O(1) Lookup)
  api/cli/                     -> action 注册表 + Execute(程序入口); action 的具体实现(启动窗口/打印版本)
```

## 3. `command.json#cli` 的最小字段集合(建议)

```jsonc
"cli": {
  "name": "automan",
  "usage": "Automan desktop & tools",
  "version": "0.0.1",              // 也可不写, 由 conf/application 提供
  "label": "root",
  "commands": [
    {
      "name": "version",
      "aliases": ["v"],
      "usage": "Print version",
      "label": "root.version",
    },
    {
      "name": "proxy",
      "usage": "Proxy utilities",
      "label": "root.proxy",
      "commands": [                 // 递归
        { "name": "list", "usage": "List proxies", "label": "root.proxy.list", }
      ]
    }
  ]
}
```

```yaml
字段集合(最小): name / aliases / usage / description / hidden / args? / flags? / action / commands
[!notice] action 在配置中不需要. label 用于O(1)映射的key用于获取实际的*cli.Command, 该结构自带Action设置字段.
[!notice] 递归: Commands 字段自引用; 建议限制深度 <= 3(防止配置写出无限层级)。
```

## 4. 结构映射(`domain/config/command.go`)

```go
// 现有: Command{ CLI map[string]any; Runtime CommandRuntime }
// 改为:
type Command struct {
    CLI     CLICommand   `json:"cli"`
    Runtime CommandRuntime `json:"runtime"`
}

type CLICommand struct {
    Name        string       `json:"name"`
    Aliases     []string     `json:"aliases"`
    Usage       string       `json:"usage"`
    Description string       `json:"description"`
    Hidden      bool         `json:"hidden"`
    Args        []CLIArg     `json:"args"`     // 见 §7 待澄清 D
    Flags       []CLIFlag    `json:"flags"`    // 见 §7 待澄清 D
    Label      string        `json:"label"`
    Commands    []CLICommand `json:"commands"` // 递归
}
```

## 5. `internal/cli/` 的职责

```yaml
Build(cfg domainconfig.CLICommand) (*cli.Command, error)
  · 把 CLICommand 递归转成 urfave/cli/v3 的 *cli.Command
  · action 名 -> 通过注入的注册表解析为 cli.ActionFunc; 未注册即报错
  · 同时构建索引: map[string]*cli.Command, key = 命令路径(空格分隔, 如 "proxy list")

Lookup(node *cli.Command, label string) (*cli.Command, bool)
  · O(1): 直接查 map; 未命中返回 false(调用方决定报错文案)

[*] 索引在 Build 时一次性建好, 运行期只读 —— 满足"快速定位"的要求, 不递归查找。
```

## 9. 风险与取舍

```yaml
· urfave/cli/v3 处于 v3 阶段, API 与 v2 差异较大(如 Command.Action 签名带 context);
  实现时以实际版本签名为准, 文档里的代码形态仅示意。
· 配置驱动的命令树: 好处是新增命令不改代码; 代价是"action 必须先在代码注册",
  因此仍有一条代码侧清单(api/cli 的 registry), 这是刻意保留的边界。
· 删除 mode() 后, "无参数 -> 启动窗口 / 有子命令 -> 执行命令" 完全交给 CLI 框架,
  不再有隐式的字符串扫描逻辑。
```
