# Bridge 通信重构设计(WebSocket over UDS)

> 协作约定: 本文件先供审阅; `[!notice]` 与方括号结论即决策;**未澄清项不擅自默认**。
> 本文**不参考现有实现**, 按四层重新定义接口与职责; 待 A–L 明确后开始编码。

## 1. 目标与范围

```yaml
目标: Go 父进程(server) 与 子进程(client) 之间的全双工通信, 承载"命令/响应 + 事件 + 流"。
技术: WebSocket(RFC6455 子集) over Unix Domain Socket; 服务端 bind/listen, 子进程 connect 并完成 Upgrade。
范围: 传输/帧/消息三层 + 业务层契约; 不含具体业务命令(whistle.* 由 service/proxy 侧注册)。
非目标: 跨机器网络、TLS、浏览器直连、多客户端聚合(一期仅 1 个 node 子进程)。
```

## 2. 分层与包布局(建议)

```yaml
domain/bridge/                  # 业务契约(唯一对业务暴露的面)
  message.go   Packet / Outgoing / Kind / Codec
  peer.go      Sender / Receiver / Handler(注册表入口)

internal/bridge/transport/      # 传输层: UDS 字节流
  listener.go  Listen(path) / Accept / Close / Unlink
  conn.go      Conn(Read/Write/SetDeadline/Close), 读写分离, 部分读处理
  errors.go    ErrClosed / ErrBackpressure / ErrTimeout

internal/bridge/frame/          # 帧层: RFC6455 子集
  handshake.go ServerUpgrade(conn) -> *Conn (校验 Sec-WebSocket-Key, 回 101)
  frame.go     opcode/掩码/长度编解码; ReadMessage 重组分片; WriteMessage
  control.go   Ping/Pong/Close 处理(含 close code/reason)

internal/bridge/message/        # 消息层: 结构化 + 关联
  client.go    (子进程侧) Dial/Request/Notify/Subscribe/pending 表
  server.go    (父进程侧) Accept/Request 转发/事件广播/流分发
  codec.go     JSON codec(默认) + 可替换 Codec
  pending.go   请求 ID -> waiter; 超时与取消

engine/bridge/                  # 引擎封装: 生命周期 + 依赖引擎 + 业务注册表
  engine.go    Init/Start/Stop; 读配置; 建立监听; 编排三层
  registry.go  命令注册表(name -> Handler), 默认不导出
```

```yaml
[!notice] 分层的硬约束:
  · transport 只认 []byte 与 deadline, 不认 WebSocket, 不认 JSON;
  · frame 只认"消息边界 + 控制帧", 不认业务 kind/name;
  · message 只认 Packet/Envelope 与请求关联, 不碰 socket;
  · 业务层只见 Packet/Outgoing 与 Handler, 完全不感知传输存在。
```

## 3. 各层接口(最小暴露面)

### 3.1 传输层

```go
type Listener interface {
    Accept(ctx context.Context) (Conn, error) // 阻塞直到有新连接或 ctx 结束
    Addr() string                             // socket 路径
    Close() error                             // 停止监听(不删文件)
}

type Conn interface {
    // Read 读满 p 或出错; 处理"部分读"; ctx 取消/超时返回 ErrTimeout。
    Read(ctx context.Context, p []byte) (n int, err error)
    // Write 写完整个 p; 写缓冲满时**阻塞**直到有空间或 ctx 结束(返回 ErrBackpressure/ErrTimeout)。
    Write(ctx context.Context, p []byte) error
    // SetDeadlines 由帧层设置(读超时用于 ping 周期, 写超时用于背压)。
    SetReadDeadline(t time.Time) error
    SetWriteDeadline(t time.Time) error
    Close() error   // 立即关闭 fd(不做协议层收尾; 收尾由 frame.Close 负责)
    Local() string
    Remote() string
}
```

```yaml
职责: 连接建立/保持/关闭, 字节流读写, 部分读写, deadline, 错误归一。
不负责: 帧边界、掩码、JSON、请求关联。
[!notice] 读写分离: 单 reader goroutine + 单 writer goroutine, 上层各持一个方向, 避免锁竞争。
```

### 3.2 帧层

```go
type Conn struct { /* transport.Conn + 状态 */ }

func ServerUpgrade(ctx context.Context, conn transport.Conn, timeout time.Duration) (*Conn, error)
func ClientUpgrade(ctx context.Context, conn transport.Conn, host, path string, timeout time.Duration) (*Conn, error)

func (c *Conn) ReadMessage(ctx context.Context) (Opcode, []byte, error) // 自动重组分片
func (c *Conn) WriteMessage(ctx context.Context, op Opcode, payload []byte) error
func (c *Conn) Ping(ctx context.Context, payload []byte) error
func (c *Conn) Close(code CloseCode, reason string) error // 发 close 帧 -> 等对端 close/超时 -> 关 fd
func (c *Conn) Done() <-chan struct{}                      // 连接终止通知(上层事件化)
```

```yaml
职责: 握手升级、帧头编解码、长度(7/16/64bit)、掩码(客户端->服务端必须掩码)、
      分片(FIN/continuation)、控制帧语义(ping/pong/close)、协议错误 -> 关闭连接。
不负责: 业务消息语义、请求关联、重试。
```

### 3.3 消息层

```go
type Client struct { /* 子进程侧 */ }
func Dial(ctx context.Context, path string, opts Options) (*Client, error)
func (c *Client) Notify(ctx context.Context, msg Outgoing) error                  // 单向
func (c *Client) Request(ctx context.Context, msg Outgoing, timeout time.Duration) (Packet, error) // 关联 ID
func (c *Client) On(name string, h Handler)                                       // 处理父进程下发的请求/事件
func (c *Client) Close() error

type Server struct { /* 父进程侧 */ }
func (s *Server) Request(ctx context.Context, msg Outgoing, timeout time.Duration) (Packet, error)
func (s *Server) Notify(ctx context.Context, msg Outgoing) error
func (s *Server) Broadcast(name string, data any) error                            // 事件帧
func (s *Server) On(name string, h Handler)                                        // 处理子进程上报
func (s *Server) Stats() Stats                                                     // pending/队列/丢帧计数
```

```yaml
职责: Envelope 编解码、ID 生成与 pending 表、超时/取消、错误帧映射、事件分发。
不负责: 帧编解码与 socket。
[!notice] 双向对称: 两侧都既能发请求也能收请求(子进程上报 node.log 类似"通知", proxy.started 类似"事件")。
```

### 3.4 业务层

```go
type Handler func(ctx context.Context, p Packet) (result any, err error)
// 注册表由引擎持有; 默认不导出, 只暴露 Register/Handle。
```

## 4. 线协议(wire)

```yaml
握手: 标准 HTTP/1.1 Upgrade, 路径 /bridge, 头:
  Sec-WebSocket-Key / Version:13 / Upgrade:websocket / Connection:Upgrade
  X-Bridge-Version: 3       # 协议版本(与 v2 不兼容时递增)
  X-Bridge-Codec: json      # 负载编码协商
帧: 文本帧(Sec-WebSocket-Opcode=1), payload = UTF-8 JSON
  除非 A 结论改为二进制帧(见 §12)
信封:
  { "kind": "request|response|event|error", "name": "<命令名>", "data": <任意 JSON>, "id": "<可选>" }
  · kind=request  : 需要响应, 带 id(空则接收方生成)
  · kind=response : 成功响应, id 必须回填
  · kind=error    : 失败响应, id 回填, data = {"code":"...","message":"..."}
  · kind=event    : 单向通知(无响应), name 标识事件类型
分片: 超过 maxFramePayload(默认 64KiB) 时按 continuation 分片, 接收侧重组并限制总大小(maxMessageBytes 默认 4MiB)
控制: 服务端每 pingInterval 发 ping, 超过 pongTimeout 未回 => 判定连接失效
```

```yaml
[!notice] 当前 node 侧协议版本是 2; 重构后升到 3, 两侧必须同步升级(不做双栈兼容, 见 K)。
```

## 5. 生命周期与状态机

```yaml
父进程(Server):
  Idle -> Listening -> (子进程连接) -> Handshaking -> Ready
  Ready --(连接断开)--> Reconnecting(等待子进程重连) --超时--> Degraded(拒绝新请求)
  Close: Ready/Degraded -> Draining(停收新请求, 等在途请求) -> Closed -> unlink(socket)
子进程(Client):
  Idle -> Dialing -> Handshaking -> Ready
  Ready --(socket 错误/心跳超时)--> Disconnected -> Retry(退避) -> Dialing
  Close: Ready -> Draining -> Closed
事件(经 eventbus 发布, 上层订阅, 不轮询):
  bridge.connected / bridge.disconnected / bridge.degraded / bridge.error
```

## 6. 背压(三层联动)

```yaml
现象: socket 发送缓冲满 -> write 阻塞; 接收方读得慢 -> 对方 write 阻塞。
策略:
  · transport: Write 带 deadline(默认 writeTimeout); 超时返回 ErrBackpressure;
  · frame    : 单写 goroutine + **有界发送队列**(sendQueue, 默认 256);
               队列满时 WriteMessage 立即返回 ErrBackpressure(不阻塞调用方 goroutine);
  · message  : 发送前检查 frame 队列水位; 满则返回 ErrBusy(不进入 pending), 或按配置排队(见 G);
               在途请求数上限(maxInflight, 默认 1024), 超出直接 ErrBusy;
  · 业务层   : 收到 ErrBusy 自行决定"排队/降级/拒绝"(桥接层不做隐式重试)。
可观测: Stats() 暴露 queued/inflight/dropped/backpressureCount, 并经事件通知。
```

## 7. 超时与保活

```yaml
connectTimeout   (子进程 Dial)          默认 5s
handshakeTimeout                        默认 5s
writeTimeout     (单帧写)               默认 10s
requestTimeout   (业务可覆盖)           默认 30s(start 类命令可给 60s)
pingInterval                            默认 20s
pongTimeout                             默认 10s
drainTimeout     (关闭时等在途请求)     默认 5s
closeGrace       (close 帧往返)         默认 2s
全部来自 conf/bridge.json#bridge.timeouts(见 E), 支持按项覆盖。
```

## 8. 优雅关闭

```yaml
父进程:
  1) 停止接受新连接; 2) 状态置 Draining, 拒绝新请求(ErrDegraded);
  3) 等在途请求完成或 drainTimeout; 4) 发 close 帧(1000 normal);
  5) 等对端 close 或 closeGrace; 6) 关 fd; 7) **unlink socket 文件**(仅自己创建时);
  8) 主动终止子进程(若仍存活): TERM -> 超时 KILL(与现有 proxy 停止策略一致)。
子进程收到 close 帧: 回 close 帧 -> 关闭 fd -> 退出 0(若父进程已死, 进程随之退出)。
[!notice] socket 文件在启动时: 若已存在且**无进程监听** -> unlink 后重建; 若有人在听 -> 报错退出(避免误删他人 socket)。
```

## 9. 错误分类与处理

```yaml
ErrClosed        连接已关闭(本地)        -> 调用方按"未连接"处理
ErrTimeout       deadline/ctx 超时       -> 请求失败, pending 清理
ErrBackpressure  写队列满/写超时         -> 业务可重试或降级
ErrBusy          在途请求超限            -> 立即失败, 提示稍后再试
ErrProtocol      帧/信封非法             -> 记录日志 + close(1002 protocol error)
ErrRemote        kind=error 响应         -> 原样上抛(含 code/message)
ErrDegraded      未连接/降级中           -> 立即失败, 不排队
规则: 任何错误都必须**清理 pending**(否则 waiter 泄漏); 连接断开时把在途请求统一以 ErrClosed 结束。
```

## 15. 通用接口迁移到 domain/bridge(第一批: 传输 + 帧)

```yaml
原则(先迁移后删除): 先把**契约**提到 domain, 让实现侧引用契约; 待调用方迁完再删旧路径。

新增(domain/bridge):
  transport.go : Stream(字节流: Read/ReadContext/Write/deadline/Close/Local/Remote)
                 Acceptor(Accept/Addr/Close)
                 ErrClosed / ErrTimeout / ErrBackpressure
  wire.go      : Opcode / CloseCode(含常量) / FrameConn(ReadMessage/WriteMessage/Ping/Close/Done)
                 ErrProtocol / ErrTooLarge

实现侧(engine/bridge):
  transport : `type Conn = domainbridge.Stream`; 错误改为 domain 别名;
              `var _ domainbridge.Acceptor = (*Listener)(nil)`
  frame     : Opcode/CloseCode/常量/错误全部改为 domain 别名;
              `var _ domainbridge.FrameConn = (*Conn)(nil)`
  message   : 仍自带 Kind/Envelope/Handler —— **下一批**与引擎切换一起迁移(见下)

为什么顺序是"先迁移实现侧引用, 后删旧": 旧 internal/ipc 与 bridgekit 仍在被 engine/bridge 使用,
一旦直接删除会让应用不可运行; 先把新契约接通并测通, 再在引擎切换那一步整体替换与删除。
```

## 17. 修复: 启动一段时间后自动断开(心跳误判)

```yaml
现象: 应用启动后约 20s（一个心跳周期 + grace）桥接连接被判定超时, peer 断开、子进程重连。

根因: 存活刷新只发生在**文本帧**上。
  · node 侧每 livenessMs(15s) 发的是 WebSocket **ping** 控制帧；
  · 服务端每 heartbeat(15s) 也发 ping, 对端 ws 库自动回 **pong**；
  · 但 frame.ReadMessage 把 OpPing/OpPong 在内部处理掉(自动回 pong / 回调 OnPong)后 `continue`,
    既没有把控制帧返回给上层, 也没有人给 Peer 的 lastPong 续期(Peer 创建 frame 时没传 OnPong)。
  => 空闲连接 lastPong 一直停在建立时刻, 超过 interval+timeout 即 shutdown(ErrTimeout)。

修复(在帧层提供"活动"信号, 而不是让上层猜):
  · frame.Conn 新增 SetActivityHandler(fn): **任意成功解析的帧**(含 ping/pong)都回调；
  · message.New 注入 `conn.SetActivityHandler(func(){ p.lastPong.set(now) })`,
    并删除 readLoop 里"仅文本帧刷新"的逻辑。

验证:
  · 新增 TestHeartbeatKeepsIdleConnection(PingInterval=40ms/PongTimeout=30ms, 空闲 400ms):
    修复前必然超时; 修复后连接保持, 且仍可正常发送。
  · 真实应用探针(干净 HOME) 连续运行 42s(> 2×心跳周期): 日志中只有 1 次 "bridge: peer connected",
    **没有任何 peer disconnected / timeout**。
```

## 31. 修复: 只有第一条 notice 进抽屉

```yaml

  · notice() 返回后端落库形态(Entry);

  · 勿扰: Push 返回空 id -> upsert 直接跳过(既不排队也不 toast), 语义不变
```
