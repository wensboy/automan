# Environments 服务设计(统一环境调用)

> 协作约定: 先本文档明确细节, **确认后再执行**; 标记「待确认」的条目需要拍板。
> 参考既有约定: service 层承载业务语义、engine 只做通用能力; 服务间依赖通过 `With*` 注入。
> 注意 notice 语义块!!!

## 1. 目标与边界

```yaml
目标:
  · 为整个系统提供**统一的环境变量读取口**: 任何服务/前端都从 environments 服务取值;
  · 环境以「目录分组 + 文件挂载点」组织, 一个文件即一份 env 文档(JSON);
  · 提供树的读写能力: 建目录 / 建文件(模板生成) / 删目录 / 删文件 / 树形路径 / 单文件内容;
  · 服务级实现: 文件读写、模板填充、并发控制都在 service/environments 内完成, 不下沉到 engine。

非目标(本期):
  · 不以数据库存储环境(保持文件可读、可版本管理);
  · 不做跨机器同步 / 加密存储;
  · 不做 watch 实时推送(先以显式刷新 + 读缓存失效为主)。
```

## 2. 目录与文件布局

```yaml
根目录: <store root>/environments           # 与 theme.json / font.json 同级
  例: ~/.config/automan/environments/

分组: 目录即分组, 允许多级
挂载点: 一个 *.json 文件
  · 一个文件内的 meta.entry 指向该文件的环境数组(默认 "environments")
  · 所有 key 均为**顶层 key**, 不做嵌套

示例:
environments/
  default/
    api.json
    database.json
  staging/
    api.json
```

```yaml
路径规则:
  · 对外统一用**相对路径**(以 environments/ 为根), 分隔符固定 "/";
  · 路径必须为相对、不可包含 ".."; 仅允许 [a-zA-Z0-9._-] 与 "/";
  · 目录路径不带扩展名; 文件必须以 .json 结尾。
```

[!notice: env 相关的配置文件在 data/conf/environments.json, 目录位置通过 config engine 获取, 不存在时需要自动创建]

## 3. 领域契约(domain/environments)

```go
// 节点类型
const (
    NodeDir  = "dir"
    NodeFile = "file"
)

type Node struct {
    Name     string  `json:"name"`
    Path     string  `json:"path"`     // 相对路径
    Type     string  `json:"type"`     // dir|file
    Children []Node  `json:"children,omitempty"`
}

// 单文件内容: 原文 + 解析后的扁平 kv(便于调用方直接使用)
type Document struct {
    Path    string            `json:"path"`
    Content string            `json:"content"`            // 原始 JSON 文本(前端编辑器用)
    Entry   string            `json:"entry"`              // meta.entry
    Values  map[string]string `json:"values"`             // key -> 按 type 序列化后的字符串
    Meta    map[string]string `json:"meta"`               // 其它 meta 字段(全部 string 化)
}

// 服务提供给其它服务的读取口(方法值注入用)
type Provider interface {
    // Values 返回某个挂载点/整棵树的扁平值; 同名 key 后加载者覆盖(见 §6 优先级)
    Values(paths ...string) (map[string]string, error)
}
```

## 4. 服务实现(service/environments)

```yaml
结构:
  Service {
    root      string                  // <store root>/environments
    mu        sync.RWMutex            // 读多写少: 读 RLock, 写 Lock
    cache     map[string]Document     // 按 path 缓存解析结果(写操作精确失效)
    data      fs.FS                   // data/default (env.tpl.json 模板)
    logger    log.Logger
    notifier  notice.Publisher
  }

文件操作(全部在服务内, 不新开引擎):
  · 读: os.ReadFile -> 解析校验 -> 返回 Document
  · 写: 序列化 -> 写同目录临时文件 -> fsync -> rename(原子替换)
  · 建目录: MkdirAll; 建文件: 模板填充后写入(见 §5)
  · 删目录: 默认仅允许空目录; recursive=true 时 RemoveAll(前端暂不开放)
  · 删文件: Remove

缓存:
  · 读路径缓存(Document), 写操作按前缀精确失效(目录删除清空其下全部缓存)
  · 不做自动 watch; Refresh(path) 显式失效(前端"Refresh"菜单走这里)
```

## 5. 模板与填充语义

模板: `data/default/env.tpl.json`

```json
{
  "meta": { "path": "{{dir}}/{{filename}}", "entry": "environments" },
  "environments": [
    { "type": "<int|bool|float|string|array|object>", "key": "example key", "value": "example value" }
  ]
}
```

```yaml
填充规则:
  · 仅替换 `{{name}}` 形式(前后不出现多余字符), 未知占位符直接报错(避免静默写坏文件);
  · 支持的语义变量(本期):
      {{dir}}      新建文件所在目录(相对根, 根目录为空串)
      {{filename}} 文件名(含 .json)
      {{entry}}    默认 entry 名称("environments")
  · 替换仅发生在**文本层**(不是 JSON 序列化后), 因此模板里的注释/缩进被保留;
  · 替换后必须通过 JSON 解析 + §3 的结构校验, 否则拒绝写入(不产生半成品文件)。
```

```yaml
建文件入参(前端"New file"后可继续编辑内容, 因此允许可选初始条目):
  { path: "default/api.json", entries?: [{type,key,value}] }
  · entries 为空 -> 使用模板中的示例条目(便于立即编辑)
  · entries 非空 -> 覆盖模板的 entry 数组(同样走类型校验)
```

## 6. 多服务调用注入(避免互相 import)

```yaml
原则: 依赖"方法值", 不依赖对方 service 包类型。

在 domain/environments 定义窄接口:
  type Lookup func(paths ...string) (map[string]string, error)

其它服务通过 With* 注入:
  proxy.WithEnvironments(func() (map[string]string, error) { return envSvc.Values("default/api.json") })
  或统一形态: WithEnvLookup(lookup environments.Lookup)

取值优先级(仅用于展示/回退, 本期不实现多文件合并): 本期 Values(paths...) 仅支持
  单文件或"全部文件"两种用法; 同名 key 冲突时报错而不是静默覆盖。
```

## 7. API 契约(api/web/environments.go)

```yaml
Tree()                         -> []Node                        # 树形路径
Read(path string)              -> Document                      # 单文件内容(原文+values)
CreateDir(path string)         -> Node                          # 创建分组
CreateFile(path string, entries []Entry) -> Document            # 模板生成挂载点
DeleteDir(path string, recursive bool)   -> error               # 默认仅空目录
DeleteFile(path string)        -> error
Refresh(path string)           -> Document                      # 失效缓存并重读
```

```yaml
错误约定(沿用 apperr):
  · 路径非法(相对/越界/字符集/扩展名)     -> CodeInvalid, 明确文案
  · 已存在(目录/文件)                     -> CodeAlreadyExists(若无则新增)
  · 不存在                                -> CodeNotFound
  · 目录非空删除                          -> CodeFailedPrecondition(文案建议递归)
  · 模板占位符未知 / JSON 校验失败        -> CodeInvalid(指出占位符或字段)
```

## 8. 并发与一致性

```yaml
· 读多写少: RWMutex; 单文件写入为"临时文件 + rename", 读取不会看到半截内容;
· Values() 读取多个文件时在同一 RLock 内完成快照, 避免跨文件读到不同版本;
· 缓存与磁盘一致性: 所有写操作在持锁期间更新缓存(或直接失效), 不使用时间过期;
· 目录递归删除与并发读: RemoveAll 前先清缓存, 读操作若发现文件已消失按 NotFound 返回。
```

## 9. 前端对接

```yaml
· lib/environment.ts 扩展为 API 适配: tree/read/createDir/createFile/delete/refresh
· Environment 页面:
    - 侧栏树 = Tree()
    - list 模式 = Read(path) 的 values(只读)
    - file 模式 = Read(path).content(可编辑; 保存走后续 Update 接口, 本期先不落盘)
    - 右键动作 -> 对应 API; 成功后 Refresh 相关节点
· 错误统一用 EmptyState(error icon) 呈现(已具备)
```

## 14. 编辑保存(UpdateFile)

```yaml
后端:
  · service.UpdateFile(path, content) -> Document
      - 校验路径(.json/相对/无 ..)
      - 文件必须存在
      - 内容整体走 parseDocument(meta.entry/条目/type/value/maxEntries 校验)
      - 校验通过后由 store 引擎原子写; 成功后更新缓存并发 notice
  · api/web: UpdateFile(path, content)
  · 测试: 保存后值/缓存同步; 非法内容(meta 缺失)返回 ErrInvalidFile

前端:
  · file 模式仍为唯一编辑入口; 编辑后 dirty = editor !== doc.content
  · dirty 时在文件名右侧出现 save icon button(保存中 disabled)
  · 点击保存: 调 UpdateFile -> 用返回的 Document 覆盖 doc/editor => 按钮自动消失
  · 保存失败: notify(error) 并在 list/file 中保留原始错误文本(不吞错)
  · 不做自动保存(符合"手动点击保存"的约定)

验证: go test ./backend/... -> 22 包全过; 前端 tsc + build ✓
